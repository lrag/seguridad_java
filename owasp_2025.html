1. Introducción

El OWASP Top 10:2025 no es solo una lista de vulnerabilidades; es un estándar de concienciación que refleja los cambios en la arquitectura moderna. En esta edición, se observa una transición clara de "errores de programación" hacia "errores de arquitectura y cadena de suministro".

2. A01:2025 – Broken Access Control (Control de Acceso Quebrado)

El control de acceso garantiza que los usuarios no puedan actuar fuera de sus permisos previstos. Cuando falla, los atacantes pueden acceder a funciones privilegiadas o datos de otros usuarios.

  • Naturaleza del riesgo: Es la vulnerabilidad número uno debido a su alta prevalencia. Ocurre cuando las restricciones no se aplican en el lado del servidor de manera centralizada.

  • Escenarios comunes:

    • IDOR (Insecure Direct Object Reference): Modificar un ID en la URL (/api/user/123 a /api/user/124) para ver datos ajenos.

    • Elevación de Privilegios: Un usuario estándar accediendo a rutas de /admin.

    • Autorización incorrecta.

    • Modificación de tokens de autenticación.

    • CORS mal configurado.

    • Force browsing (adivinar rutas)

  • Mitigación:

    • Implementar el principio de Mínimo Privilegio.

    • Centralizar los mecanismos de control de acceso y evitar comprobaciones dispersas en el código.

    • Asegurar la comprobación de la autorización lo más cerca posible de las funcionalidades.

3. A02:2025 – Security Misconfiguration (Configuración de Seguridad Incorrecta)

Con el auge de la infraestructura como código (IaC) y la nube, las malas configuraciones se han vuelto críticas.

  • Naturaleza del riesgo: No se trata de un error de código, sino de dejar "puertas abiertas" por defecto.

  • Escenarios comunes:

    • Permisos de lectura públicos en buckets de S3 o bases de datos sin contraseña.

    • Servicios innecesarios instalados (puertos abiertos, páginas de ejemplo).

    • Cabeceras de seguridad HTTP (HSTS, CSP) ausentes o mal configuradas.

  • Mitigación:

    • Proceso de Hardening (endurecimiento) automatizado.

    • Auditoría continua de la configuración de red y nube.

4. A03:2025 – Software and Data Integrity Failures (Fallos de Integridad de Software y Datos)

Este riesgo se centra en la suposición de que el software o los datos que consumimos son legítimos y no han sido alterados.

  • Naturaleza del riesgo: Incluye la Deserialización Insegura, donde objetos maliciosos pueden ejecutar código al ser procesados por la aplicación.

  • Escenarios comunes:

    • Aceptar objetos serializados de fuentes no confiables.

    • Actualizaciones de firmware o software que se descargan sin verificar su firma digital.

    • Confiar en actualizaciones automáticas

    • Utilizar librerías de origenes sin comprobar

  • Mitigación:

    • Utilizar firmas digitales para validar fuentes.

    • Evitar la deserialización de datos binarios; preferir formatos planos como JSON validado.

5. A04:2025 – Cryptographic Failures (Fallos Criptográficos)

Anteriormente conocido como "Exposición de Datos Sensibles", se enfoca en la protección de la información crítica mediante cifrado.

  • Naturaleza del riesgo: El uso de algoritmos obsoletos o la gestión incorrecta de claves hace que el cifrado sea inútil.

  • Escenarios comunes:

    • Almacenar contraseñas con hashes débiles (MD5, SHA1) en lugar de Argon2 o BCrypt.

    • Transmisión de datos sensibles sobre canales no cifrados (HTTP, FTP).

  • Mitigación:

    • Cifrar todos los datos sensibles en reposo y en tránsito.

    • Implementar una gestión de claves robusta (Key Management).

6. A05:2025 – Injection (Inyección)

En 2025, esta categoría agrupa la inyección en lenguajes de consulta y Cross-Site Scripting (XSS). Ocurre cuando datos controlados por el usuario son interpretados como comandos por el sistema.

  • Naturaleza del riesgo: El sistema confunde datos con instrucciones.

  • Escenarios comunes:

    • SQL Injection: Consultas construidas concatenando cadenas.

    • XSS (Cross-Site Scripting): Scripts de JavaScript inyectados en el navegador del usuario para robar sesiones.

  • Mitigación:

    • Uso estricto de Consultas Parametrizadas (Prepared Statements).

    • Validación de entradas y codificación de salidas (Output Encoding) según el contexto.

7. A06:2025 – Insecure Design (Diseño Inseguro)

A diferencia de los errores de implementación, aquí el problema reside en la concepción de la aplicación.

  • Naturaleza del riesgo: Una aplicación puede estar programada "perfectamente" según sus requisitos, pero sus requisitos son inherentemente inseguros.

  • Escenarios comunes:

    • Generar flujos de recuperación de contraseña basados en preguntas predecibles.

    • Diseñar sistemas financieros que permitan saldos negativos por falta de lógica de validación arquitectónica.

  • Mitigación:

    • Realizar Modelado de Amenazas (Threat Modeling) antes de codificar.

    • Integrar la seguridad en el ciclo de vida desde el diseño (Shift Left).

8. A07:2025 – Identification and Authentication Failures (Fallos de Identificación y Autenticación)

Se refiere a los problemas para confirmar la identidad de un usuario de forma segura.

  • Naturaleza del riesgo: Si la puerta de entrada es débil, el resto de los controles no importan.

  • Escenarios comunes:

    • Permitir ataques de relleno de credenciales (Credential Stuffing).

    • Sesiones que no expiran o que son predecibles.

  • Mitigación:

    • Implementar Autenticación Multifactor (MFA).

    • Políticas de contraseñas fuertes y gestión segura de sesiones.

9. A08:2025 – Software Supply Chain Failures (Fallos en la Cadena de Suministro de Software)

Nueva categoría crítica debido a la dependencia masiva de terceros.

  • Naturaleza del riesgo: El compromiso no está en tu código, sino en las herramientas que usas para construirlo.

  • Escenarios comunes:

    • Inyección de código malicioso en una biblioteca de código abierto popular (npm, PyPI).

    • Compromiso del pipeline de CI/CD para insertar backdoors en el binario final.

  • Mitigación:

    • Mantener un SBOM (Software Bill of Materials) actualizado.

    • Analizar dependencias en busca de vulnerabilidades conocidas (SCA - Software Composition Analysis).

10. A09:2025 – Security Logging and Alerting Failures (Fallos de Registro y Alerta de Seguridad)

Este punto trata sobre la visibilidad post-incidente y la detección temprana.

  • Naturaleza del riesgo: Sin registros, no hay forma de saber que un ataque está ocurriendo o cómo sucedió.

  • Escenarios comunes:

    • No registrar intentos de inicio de sesión fallidos o acciones administrativas.

    • Logs que no se centralizan y se pierden si el servidor es comprometido.

  • Mitigación:

    • Centralizar logs en un sistema externo protegido.

    • Configurar alertas para actividades sospechosas (ej. múltiples fallos de acceso en corto tiempo).

11. A10:2025 – Mishandling of Exceptional Conditions (Gestión Inadecuada de Condiciones Excepcionales)

Nueva categoría que aborda la resiliencia y el comportamiento del sistema ante el error.

  • Naturaleza del riesgo: Cómo reacciona el sistema cuando algo sale mal. Un mal manejo puede revelar secretos o saltarse protecciones.

  • Escenarios comunes:

    • Fuga de Información: Mostrar el Stack Trace completo al usuario final.

    • Fail Open: Un control de acceso que, ante un error de base de datos, permite el paso por defecto.

  • Mitigación:

    • Implementar un manejo de excepciones global y amigable.

    • Aplicar el principio de Fallo Seguro (Fail-Safe): si hay duda o error, el acceso se deniega.
